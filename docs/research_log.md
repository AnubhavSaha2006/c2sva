## Round 1 — 2026-11-20 — Reframing A1 after the ablation (what survives HLS, and why)

**Observation to explain.** Ablation: HLS-structural candidates alone certify 12/16 contracts; C proof artefacts are decisive on 3 designs + ABE `find` (all array-quantified loop invariants); contract-derived facts on 1 (c02). C loop invariants hold verbatim on RTL for 16/21. A reviewer will say "A1 is AutoINV plus a small bonus". The reply must be a *theory predicting the split* and a measurement protocol, not a bigger win-count.

**Key prior work found for the framing.** Namjoshi & Zuck, "Witnessing Program Transformations", SAS 2013, LNCS 7935 [v]: a transformation emits a *witness* (a stuttering simulation, shown sound and complete as witness format); any invariant of the source is turned into an invariant of the target by composing it with the witness; witnesses compose over a pass sequence. Also Beyer-style correctness witnesses (location-based invariants; Software Verification Witnesses 2.0, SPIN 2024 [unv]) and witness validation by abstract interpretation (arXiv 2310.16572 [v] as a title). Mukherjee, Schrammel, Kroening, Melham, "Unbounded safety verification for hardware using software analyzers", DATE 2016 [v]: RTL→C then software engines (k-ind, IC3, interpolation) — opposite direction (RTL checked as software), no source proof reuse. AutoINV (Zhou, Du, Hu, Sinha, Zhang, Zhang, arXiv 2604.22285, Apr 2026) [v]: HLS-structure helper assertions, avg 2.23x / peak 6.05x speed-up on IC3; no source artefacts. Kairos (Piccolboni et al., FMCAD 2019) [v as title]: incremental verification in HLS, different goal.

### Framing 1 (recommended): "Witness-guided invariant transport with an *untrusted, partial* witness; theory of the structural/semantic split"

*Core claim.* Vitis (schedule/bind reports + RTL naming) is a *de facto, untrusted, partial witness* in the sense of Namjoshi–Zuck. Differences that make it new: (i) black-box commercial tool: the witness is *inferred*, not emitted; (ii) target property is a contract, so only the contract-relevant observables need simulation, not full equivalence; (iii) the transported facts are *checked on the target* (Houdini + k-induction), so a wrong/partial witness costs completeness, never soundness (already Theorem 2 in docs/theory.md) — i.e. "witness-carrying, target-checked".

*The explanatory theorem (the part that is new and predicts the ablation).* Let W ⊆ RTL×C be the (partial) refinement relation and dom W ⊆ RTL states the set where it is defined (control position + registers holding live C values). A C invariant I transports to γ(I) = {s | ∃c. W(s,c) ∧ I(c)}. k-induction quantifies over *all* RTL states, including those outside the reachable set, so γ(I) is inductive **only relative to an invariant describing dom W** (FSM one-hot/state-range, counter ranges, affine register relations, "register r is live in state q"). Hence the certificate splits canonically:
  1. *Domain part* (control skeleton + affine relations): derivable from RTL/report structure alone — this is exactly AutoINV-style/HLS-structural candidates. Explains 12/16.
  2. *Semantic part* (history predicates: ∀k<i. a[k]≠x, prefix sorted, prefix copied; memory-content facts tied to loop position): has **no structural source** because the information lives in the memory array, which the RTL structure does not constrain. Only the C proof (or an LLM/mining) can supply it. Explains 3 designs + `find`.
  Falsifiable prediction (cheap to test on existing data, 17 + 72 + ACSLBench designs): *C artefacts are necessary iff the WP loop invariant contains a quantifier over memory (or the contract post needs a history predicate not implied by control state)*. Report a confusion table: syntactic feature "quantified-over-array loop invariant" vs observed C-necessity. If it holds, it is a result with a mechanism, not a win count.

*Survival taxonomy (why 5/21 C invariants fail verbatim — to be filled by inspecting the 5).* Hypotheses to check against the failing ones: (a) variable not materialised (strength reduction i→pointer, scalar replacement, induction-variable merging, partition-complete array → per-element regs); (b) co-liveness: register sharing by binding means v is mapped only while live, so I holds only under a guard "v is current"; (c) speculation/hoisting: loop exit test / array read executed one iteration early (a[i] with i=n), so I needs weakening `i<=n` vs `i<n` or an off-by-one stage offset; (d) pipelining: I must be instantiated per stage; (e) nonlinear re-association (c10). Each class gets a repair operator in the candidate generator (affine-equality templates for (a): r = c·r' + d mined from traces; liveness guard from the schedule report for (b); weakened/shifted variants for (c),(d)).

*Experiments / metrics.*
  - E-split: structural-closure vs +C vs +contract on all designs; define **semantic residue** ρ = |minimal certified set| − |minimal structural-only certified closure|, found by delta-debugging the Houdini survivors (each probe is one k-induction run, seconds). Report ρ and k_min with/without C artefacts.
  - E-predict: confusion table above.
  - E-portability (answers RQ5 formally): a *single* source-level certificate (C invariants, no edits) vs the 11 Vitis configs; fraction of configs where it certifies without hand edits, and which taxonomy class causes each failure.
  - E-baseline: AutoINV-like structural-only Houdini as the baseline (already the `hls` ablation); keep it honest.
Effort: S–M (mostly analysis scripts over prove.json + a delta-debug loop in prove.py). Risk: low; worst case the prediction fails and the taxonomy becomes the contribution. Venue fit: FMCAD/TCAD for theory + survival study.

### Framing 2: Floyd–Hoare cut-point proofs on RTL with the HLS schedule as the segment map ("Hoare logic over schedules")

*Idea.* Do not ask for one global k-inductive invariant. Use WP loop invariants as *cut-point assertions* at the FSM states that correspond to loop headers (and callee entry/exit, from the schedule report). Prove three kinds of short segments by BMC from a *symbolic* RTL state constrained only by the cut-point assertion + domain invariants: entry (call start → first header, ≤ prologue latency), preservation (header → next header, ≤ body latency L, or L·depth for pipelined loops), exit (header ∧ ¬cond → ap_done ∧ Post). Depth is bounded by *body latency*, independent of trip count and of N; nested loops compose via the inner loop's own triple (inner contract as a segment summary), and an inlined callee's ACSL contract is the segment summary for its FSM region — this is the natural attack on equal_range (callee loops inlined into one FSM), where name-based invariants failed.
*Why new.* Cut-point/refinement-map style SEC for HLS exists (Kundu et al. CAV 2008; Ray et al. ATVA 2009; Hector-style SEC [unverified in detail]) but proves C≡RTL equivalence in research tools; k-induction-with-invariants for RTL (Xu & Josipović ICCAD 2023) is whole-circuit. A Hoare-triple decomposition of a *black-box* RTL schedule where the segments come from a *source contract proof* is, to our knowledge, not published (re-run search before submission).
*Relation to k-induction.* A cut-point segment proof is k-induction with a loop-aware, variable-length unrolling; its advantage is that the symbolic start state has a fresh, small frame (only registers live at the header) and the depth is the *loop body latency*, so it should scale where uniform k=4..16 does not (nested loops, long bodies). Cost: need reliable (header state, live-register) maps → feeds Round 2.
*Experiment.* Same 17+72 designs: (i) k_needed vs segment depth; (ii) solver time of monolithic k-ind+Houdini vs segment proofs as latency scales (N=4..16, nested loops); (iii) equal_range solved or not. Effort: M–L (needs per-cut-point harness: assume-at-header via `$initstate`-free symbolic start; sby cannot start from arbitrary state directly — use `-nounset`/anyinit with an assumption that FSM==H at step 0, then assert at the next visit step; the existing tap machinery in prove.py already reads internals). Risk: medium (liveness map quality).

### Framing 3: Contract-level proof *reuse across source refactorings* (the role of the C proof as the stable element; links RQ5 and RQ6)

*Idea.* Rewriting HLS-C (unrolling, tiling, loop reversal, strength reduction, LLM-generated "synthesizable" rewrites such as C2HLSC outputs) changes the code but not the contract; the original deductive proof's invariants, phrased on *abstract state* (prefix/array/ghost) rather than on C variables, are the part of the proof most likely to remain valid. Define a candidate family *parametric in the register mapping* (search over which RTL register plays "i": affine template r = c·i' + d fitted on traces) and test certification of the rewritten design's RTL against the *original* contract and *original* invariants.
*Closest prior.* Pouchet et al., FPGA 2024 (formal verification of source-to-source transformations for HLS) [v via earlier survey] verifies C→C equivalence, not contract/RTL; Namjoshi–Zuck transport needs a witness per transformation, here the witness is *inferred on the RTL side*; LLM HLS-C rewriting papers (C2HLSC TODAES 2025; arXiv 2606.17128, 2606.28409 from survey) validate by testing.
*Experiment.* 10–20 ABE/conformance designs × 4–6 hand-written transformations (unroll ×2/×4, manual strength reduction, loop reversal when legal, split/fuse loops, temp-array buffering) + a few LLM rewrites; metric = fraction certified unbounded with original certificate pool vs structural-only vs failing; failures classified by the Round-1 taxonomy. Effort: M. Risk: medium; strong story for "formal safety net for LLM-written HLS-C".

### Ranking and recommendation
1. Framing 1 (theory + residue/portability measurements) — cheapest, makes the existing ablation the *main result*; should be the paper's spine together with A2.
2. Framing 2 (cut-point/Hoare over schedules) — highest novelty ceiling and the only credible fix for equal_range-type designs; do after Round 2's correspondence.
3. Framing 3 — best application story (RQ5/RQ6), builds on 1 and 2.
Additional cheap metric ideas: *minimal k* and *minimal certificate size* per design with/without each family; "proof-reuse ratio" across the 11 configs (invariants reused verbatim / total); "certificate transport survival matrix" (invariant × HLS transformation).

## Round 2 — 2026-11-20 — Correspondence beyond name matching: the Vitis reports already contain a binding witness

**Finding from reading the equal_range reports** (runs/E3_abe/cases/BinarySearch__equal_range/vitis/base/original/hls/proj/sol/.autopilot/db/; confirmed also on c07). Vitis does not just give names; it gives a *machine-readable binding map* in four places:
 1. `<mod>.verbose.rpt` (and `.verbose.rpt.xml`, `.bind.adb(.xml)`): a list of `<comp name="left_fu_40"> <bind><opcode="alloca"/><opset="left/1 "/>`: RTL component ↔ the **set of LLVM ops bound to it** (shared FUs list several ops). `fu_N` = component id.
 2. `<mod>.verbose.sched.rpt`: per op, its FSM state (`ST_3 : Operation 31 ... store %left_6 → %left`), its source location **with inline chain** (`lower_bound.c:6->equal_range.c:9`), and the pipeline summary (II, D, state set).
 3. `<mod>.bind.adb.xml`: CDFG with basic-block labels (`while.cond.i`, `while.body.i`), op order and `<dataflow from to>` def-use edges (gives live ranges).
 4. The call ops of the parent (`call @equal_range_Pipeline_VITIS_LOOP_17_1(n_read, a, v_read, first_loc)`): argument map to the sub-module ports.
Naming algebra seen in the Verilog (equal_range sub-module and c07): alloca `x` → register `x_fu_<id>`; `%y = load %x` → combinational `ap_sig_allocacmp_<y>` (a **forwarding mux** between the register and the value being written by the iteration still in flight); op result `%z` crossing a state boundary → `z_reg_<n>`, else `z_fu_<n>_p<k>`.

**Why the name-based map failed on equal_range (hypotheses to test, cheap):**
 - Two callee loops both use locals `left`/`right`; the unambiguous key is (callee loop `lower_bound.c:17`, inline chain `->equal_range.c:9`) ↔ sub-module `Pipeline_VITIS_LOOP_17_1` (the second chain `->equal_range.c:10` ↔ `_17_11`). Loops in callees are *separate pipelined sub-FSMs with their own ap_start*, called from the top FSM (states 1–4), not one flat FSM.
 - The C value of `left` at the loop header is `ap_sig_allocacmp_first` (the forwarded value, valid iff `ap_enable_reg_pp0_iter0`/first-stage active), **not** `left_fu_40`, which lags one update behind when the II=1, depth-3 loop is full. `right` ↔ `ap_sig_allocacmp_right_3`. A mixed pair (a stale `left_fu_40` with a forwarded `right`) breaks relational invariants (`left <= right`, quantified prefix facts). Test: add the allocacmp signals as the *only* placement and rerun Houdini on equal_range.
 - Callee parameters `a,n,v` are sub-module ports (`n`, `a`, `v`, captured in `v_read`) whose views must be bound to the top's captured inputs through the call args.

**Algorithm sketch ("binding-witness extraction", ~400 lines Python, new `src/c2sva/binding.py` feeding `invariants.py`; no tool run needed beyond what `hls.py` already collects):**
 1. For each module M (top and `*_Pipeline_*`/callee sub-modules): parse alloca ops (C locals, with src line + inline chain), the BB labels, and loop headers (`VITIS_LOOP_<line>_<k>` ↔ ACSL loop at that line of that source file; use the chain's outermost frame to name the instance).
 2. C value of local `x` at header H = the SSA def reaching H: `load %x` in the header BB (→ `ap_sig_allocacmp_<y>` if present in Verilog, else `x_fu_<id>`) or a `phi` (→ `ap_phi_*`, name pattern to be checked in a design with unpipelined for-loops). Emit exactly **one placement** per (loop, var), guarded by "first-stage state of H" (non-pipelined: the FSM state(s) of the header BB; pipelined: `ap_enable_reg_pp0_iter0` ∧ state), not "all placements × all states".
 3. Liveness window from sched.rpt (def state) and dataflow edges (last use) for registers shared by several ops (opset with >1 op): guard = union of windows. This gives co-liveness (taxonomy class (b) in Round 1) for free.
 4. Call edges: map call args to callee ports, and callee `@ap_done` to the caller state after the call; callee contract (if any) serves as summary of that region (Framing 2).
 5. Output `binding.json`; invariants.py asks it for (signal, guard) per C var; fall back to today's name heuristics if absent.
 6. **Soundness is unaffected** (Theorem 2: candidates are only hypotheses; Houdini drops wrong ones). Mapping quality is therefore a pure completeness/efficiency metric.

**Trace-based fallback (Daikon-style relational matching) for cases where the report does not name the value** (strength-reduced induction variables, partitioned arrays → per-element regs, rewritten code in Framing 3): instrument the C loop header to log (iteration, var values); log RTL regs/allocacmp wires per cycle during the existing C-replay or cosim vectors; for each C var find RTL signals r and affine (c, d) with r = c·v + d on all observations that satisfy a guard cluster (valid-bit/state). Emit r-expressions as candidates. Closest prior: Daikon dynamic invariant detection (Ernst et al., ICSE 1999/TSE 2001 — unverified here); refinement maps for ILA are user-written (ILA line [v earlier]), automatic inference from traces for *C-to-RTL* I could not find (search 2026-11-20: results were ILA/tandem simulation, Shi "Lifting hardware models from implementations", UCB TR 2022 — unverified relevance). So: "learned refinement maps for HLS", to be claimed with the usual caveat.

**Relation to translation validation of software pipelining.** Tristan & Leroy, "A simple, verified validator for software pipelining", POPL 2010 [v]: validates a modulo-scheduled loop by symbolically evaluating the pipelined body (with register renaming/modulo variable expansion) against the original body. The allocacmp forwarding mux and `ap_enable_reg_ppN_iterK` valid bits are the HLS analogue of renaming + prologue/epilogue predication. Difference: they prove *equivalence of the loop*, we need only that the *C header state sequence is observable at the first stage* (a weaker, cheaper statement) and we discharge it by Houdini/k-induction on the RTL instead of a verified validator. Option for a stronger result: add the "one steady-state iteration" segment check of Framing 2 as the formal justification that the forwarded value equals the C state.

**Experiments / metrics.**
 - Candidates per C invariant (today ≈ 600 capped for equal_range) → ≈ 1–2; wall-clock of the A1 stage; Houdini kept-ratio (precision) and fraction of C invariants kept (recall) vs the name-based map across E1 (17), E3 (72), and the 11 configs (does the *same extractor* work for unroll/partition/reshape/dataflow? measure extraction success rate per config — itself a result for RQ5).
 - equal_range and the other callee-loop ABE designs: unbounded or not (the open problem).
 - Ablation: name-based vs binding-witness vs +trace-based fallback.
Effort: M (binding.py + tests on the reports already on disk; XML formats are stable inside one Vitis version — pin 2026.1 and fail soft). Risk: report format changes across Vitis versions; dataflow/dataless designs have multiple FSMs.

**Next round should look at:** Round 3 (size-independent verification when RTL address width depends on N) — build beyond research_ideas §3.2: *width-parametric* cutoff arguments (re-synthesis at several N + inductive argument over certificate shape), tracked-cell/prophecy memory, and what exactly is provable about the deployed N from N=4,8 evidence.

## Round 3 — 2026-11-20 — Size-independent verification when RTL address width depends on N

Builds beyond research_ideas §3.2 (2a tracked-cell memory, 2b data independence, 2c small-model). New material: (i) the right *target* of a parametric argument, (ii) a harness change that is exact for the Skolemizable fragment and needs no RTL abstraction, (iii) a size-dependent semantic effect that any cutoff theorem must respect, (iv) a concrete, honest family-certificate protocol.

**Sources checked [v]:** Monniaux & Alberti, "A Simple Abstraction of Arrays and Maps by Program Translation", SAS 2015 (pp. 217–234); Conchon & Goel, "Invariants for Finite Instances and Beyond", FMCAD 2013 (title/venue from search: generalise invariants of finite instances to the parameterised family and check them parametrically); "Completeness Thresholds for Memory Safety of Array Traversing Programs" (arXiv 2305.03606; title only — worth reading: a CT of BMC for array-traversing loops with symbolic size is a direct fit for RQ3/RQ4); invisible invariants (Pnueli et al.; seen in search snippet as a method: small-instance candidate invariants checked symbolically). [unv] Mann–Irfan–Griggio–Padon–Barrett prophecy for arrays (TACAS 2021; from the earlier survey).

### Idea 3.1 — Make the *C proof* the size-independent part; verify only the HLS step per deployment ("what must be parametric is the refinement, not the algorithm")
WP already proves the algorithm for all `n`. What N=4 changes is the *circuit* (address width w=⌈log₂ N⌉, loop-bound compare widths, partition/reshape word counts). So a faithful claim is per **deployment depth D**: "the RTL Vitis generates for `T a[D]` preserves the contract (for all n ≤ D, any number of calls)". State this in docs/theory.md as the **deployment-specialised contract** `Pre_D = Pre ∧ valid ranges ⊆ [0,D)` — it makes explicit that N is a modelling choice and D is the user's. Two routes to cover all D: (a) per-D proofs for a ladder D ∈ {4, 8, 64, 1024, 2^16} (cheap, see 3.2) = *unbounded in calls/latency, specific in D*; (b) a family argument (3.4).

### Idea 3.2 — Array-memory harness with tracked Skolem cells (exact for the ∀-in-assertion / ∃-in-assumption fragment)
Today `harness.py` instantiates one register per C cell (`m_<a>_<i>`) plus a snapshot (`o_<a>_<i>`), so state grows with N and 2×N registers hurt BMC/IC3. Observation: c2sva's polarity lemma already turns every ∀ in an assertion (and ∃ in an assumption) into a solver-chosen symbolic index (`anyconst`), i.e. **these clauses never needed N cells**. Change: `reg [dw-1:0] mem[0:D-1]` (kept as an SMT array by `write_smt2`, no `memory_map`; check sby/yosys flags — not run here) driven by the same `locate` write/read logic, and for each symbolic index `k` a pair `(mem[k]` current view, `o_k` snapshot captured at `h_start_evt`). Pre/post/`\old` views for index terms `a[k]`, `a[k+1]`, `a[i+j]`... are `mem[term]` and snapshot registers *per index term* (not per cell). The harness is then O(#index terms), independent of D: D=2^16 costs the same as D=4 for BMC and k-induction. Enumerated constructs (`\sum`, `\numof`, ∃ in assertion, ∀ in assumption, frame "no other cell changed" over all cells) keep the N-cell mode, reported as "N-bounded clause" (already tracked by translate.py's polarity table). The frame condition for `assigns` is itself ∀-in-assertion over a symbolic index (`k ∉ assigns ⇒ mem[k]==old[k]`), so it fits.
 - Closest prior: array abstraction by cell/Skolem tracking (Monniaux–Alberti SAS 2015 [v]; Mann et al. TACAS 2021 [unv]); ILA/EMM memory modelling in BMC. Novelty is *where* the abstraction lives: in HLS RTL the array exists only behind the interface (no internal copy unless local arrays), so replacing the harness memory is an *exact* abstraction of the environment with no RTL abstraction.
 - Experiment: ABE/ACSLBench designs whose clauses are all Skolemizable: BMC/k-ind time and max depth vs D ∈ {4,…,2^16}; expect flat curves vs exponential today. Effort M (harness.py + translate.py index-term bookkeeping). Risk: sby k-induction with `$mem` (check support), `partition complete` layouts (still per-element, size-bound by design).

### Idea 3.3 — Demand-driven instantiation of ∀-in-assumption facts on RTL *access addresses* (the hard part: sortedness preconditions)
`requires \forall i<j. a[i] <= a[j]` (binary search family, equal_range) is ∀ in an assumption → enumeration O(N²). With an array memory, instantiate it lazily on the addresses the RTL actually touches: at each cycle where the RTL issues a read (address `A_t`, data `Q_t`) assume `P(A_t, Q_t)` and pairwise `P`-consistency with a **bounded window of previous accesses** (last r reads plus the tracked Skolem cells). This is E-matching with the memory interface as trigger set. Sound for proofs (a *weaker* assumption than the real ∀ ⇒ PASS implies PASS under the full assumption; both base and step of k-induction, because instances are only ever dropped, never invented); incomplete when the proof needs an unseen pair, and then a spurious CTI says which pair to add (CEGAR over instance sets; the C replay oracle still catches real failures). The *C loop invariants* supply exactly the missing semantic instance (e.g. `a[left-1] < v`), which gives the first **mechanistic link between "C proof necessary" (Round 1 residue) and "quantifier instantiation needed"** — a testable claim: the residual invariants are those whose instances are not reachable from window-local pairs.
 - Effort L, Risk medium-high; payoff: unbounded-N proofs of the binary-search/sorted-array class, currently bounded(k) or open.

### Idea 3.4 — A *size-dependent semantic effect* that any cutoff/family argument must carry: speculative-access aliasing modulo 2^w
Existing finding: `is_sorted` n=4 reads `a[4]`; with a 2-bit address the access wraps to `a[0]` (benign `speculative`); with `bram` it is a real OOB. Consequence for parametric claims: **for D a power of two the wrap is benign-by-aliasing, for D not a power of two the same RTL pattern reads cells D..2^w−1, which exist physically only if the BRAM is that large** — the access outcome (`ok | speculative | out-of-memory`) is *not monotone in D*. Predicted table (cheap experiment, E6 already running N=2/8; add D=5, 6, 1000, 1024): outcome class vs D mod 2^w. This is a concrete, publishable "pitfall of size-generalising HLS verification", and the reason family certificates must treat access-safety as a separate per-D obligation. Combine with the earlier "access outcome" harness (already there).

### Idea 3.5 — Family certificate with an explicit uniformity witness (honest cutoff-style claim)
Protocol: (1) synthesize at D₀<D₁<D₂ (e.g. 4, 8, 16, 64); (2) normalise netlists (yosys `proc; opt_clean; flatten`, names from Round 2's binding map) and check **structural isomorphism modulo widths and D-derived constants** (the `fu_<id>` naming makes the alignment unambiguous); (3) run Houdini/k-induction at D₀, D₁ and the *size-independent array harness of 3.2* at D₂ and target D; (4) report "certified for D ∈ {…}" per deployed value plus "family-uniform for D ∈ [D₀, D₂] (structural check passed)". The step from sampled D to *all* D is a **trusted assumption on the HLS tool (T4: uniform in D beyond D₀)**, stated like T1–T3 in theory.md, never claimed as proved. This is the analogue of invisible invariants / Conchon–Goel (finite-instance invariants generalised to the family [v]) with the roles reversed: the generalisation obligation is on the *compiler output*, and it is checked empirically at several instances rather than by a parametric SMT query. Novelty: first explicit "uniformity of an HLS tool across a size parameter" check; risk: Vitis may change structure at size thresholds (BRAM/LUTRAM choice, `ap_memory` latency, partition factors) — the structural-diff will *reveal* such thresholds, itself a result.

### Idea 3.6 — Unbounded D via integer abstraction of the address datapath (bridge to Round 4)
For genuinely symbolic D one needs a width-free model: replace BV address/index arithmetic by unbounded integers under *no-overflow side conditions* (e.g. `i ≤ n ≤ D ≤ 2^w−1`, proved as separate k-inductive range lemmas per w and used as hypotheses) and prove the loop/refinement with a CHC/LIA+arrays engine (Spacer/Eldarica; CHC solvers support BV and arrays, search 2026-11-20 [v] but I found no published RTL→CHC flow for HLS; hw-cbmc/EBMC word-level k-induction is an alternative backend [unv]). Treated in Round 4.

**Ranking.** 3.2 (+3.1 framing) first: small, exact, removes "N=4 is a different circuit" for the common clauses, and gives the scalability figure. 3.4 second: one experiment, a crisp new finding. 3.3 and 3.5 for the journal version; 3.6 speculative.

**Metrics to report:** (a) fraction of translated clauses Skolemizable (translate.py already knows polarity); (b) time vs D curve flat vs N-cell mode; (c) deployed-D table (D ∈ {4,64,1024,65536}) with verdict + access outcome; (d) uniformity witness: structural-diff size per D step.

**Next round should look at:** Round 4 (nonlinear arithmetic and deep designs): BV→Int/LIA abstraction with certified no-overflow side conditions (with 3.6), uninterpreted multipliers + C-level refinement oracle, requires-driven bit-width reduction, word-level IC3 (Pono/AVR/rIC3) vs k-induction on c10-style triple products; plus the LLM-in-the-loop (A3) lemma proposer using CTIs if budget allows.

## Round 4 — 2026-11-20 — Nonlinear arithmetic and deep designs (c10-class)

**What c10 is, from the artefacts.** `cube_ish`: `(long)x*y*z + x` with |x|,|y|,|z| ≤ 1000, latency 2, feed-forward, no loops. prove.json: k-induction 300 s timeout, PDR timeout, Houdini (13 candidates, 11 certified) reaches k=16 after 913 s, but the *step with invariants* and PDR+inv still time out. Cause: the property equates the RTL's 32×32→64 (then 64×32) multipliers with the harness's 112-bit spec product, i.e. a **multiplier miter between two structurally different multipliers** — the textbook hard SAT instance, independent of k or invariants. So the issue is not strengthening; it is the *arithmetic equivalence step*. All remedies must remove bit-blasting of the multiplier, or shrink it.

**Prior art found [v by title/venue unless noted].**

### Idea 4.1 — Contract-seeded, induction-certified range analysis → width reduction ("range-certified shrinking")  [cheapest, most likely to fix c10]
 1. Seed: input intervals from `requires` (linear bounds on scalars; array element bounds when present) — c2sva already parses them; interval of every captured input `x_cap`.
 2. Forward interval abstract interpretation over the *RTL netlist* (yosys `write_json` after `flatten; opt`): per-signal/register intervals through `$add/$sub/$mul/$shl/$mux/$sext`, widening at loops (few for HLS FSM datapaths; loop counters bounded by `n`'s interval). Gives candidate range invariants `lo ≤ r ≤ hi` for **every register and wire** — these are exactly the "range" candidates Houdini lacks today and AutoINV/PROMISE do not derive from source contracts.
 3. Certify: k-induction/Houdini (cheap, linear) on the range candidates alone (no multiplier equivalence needed: range of a product is implied by the operand ranges **if the operator is abstracted as the interval function** — to keep the check cheap model `$mul` here as an interval-bounded fresh value: sound over-approximation).
 4. Shrink: rewrite the netlist so that every `$mul/$add` whose operands are certified to fit in w' ≪ w bits uses w'-bit operands (the high bits are sign copies by the invariant), i.e. an explicit `wreduce` driven by *proved* invariants instead of structural width analysis. c10: operands 11 bits (|x| ≤ 1000 < 2^10), product 21, triple product ≤ 31+1 bits; multiplier miter drops from 32×32 to ~11×11, then 21×11: solved by SAT in seconds, and the harness spec is evaluated at the same reduced width.
 5. Soundness: reduction is an equivalence-preserving rewrite under certified invariants (assume-guarantee: the invariants are k-inductive in the *unreduced* model; the reduced model is only used for the property step). Document as Lemma (range-certified width reduction) in docs/theory.md; trusted base unchanged.
 Effort: M (netlist walk in Python on yosys JSON; the tap machinery of prove.py shows reading internals already works). Risk: low–medium (interval blow-up through loops; array element ranges). Fix also covers the *spec side*: shrink W from 112 to the minimal width given by the same interval analysis on the ACSL term (replacing the conservative `W = max(64, ret+8, w_param·(mul_depth+1)+16)`), a pure translate.py change that helps every arithmetic-heavy ACSLBench task even without netlist rewriting.
 Metric: # designs/clauses moving bounded→PASS/unbounded; solver time for multiplier-bearing designs; shrink factor (Σ bits before/after) per design.

### Idea 4.2 — Multiplier congruence with width lemmas + value-lemma CEGAR, with the C evaluator as refinement oracle  [for large ranges where 4.1 cannot shrink]
 Replace each `$mul` by an uninterpreted function symbol in *both* the RTL and the spec (harness) after a **width-normalisation lemma**: `trunc_w(sext_W(a) · sext_W(b)) = trunc_w(sext_{w'}(a) · sext_{w'}(b))` for all W,w' ≥ operand width (ring homomorphism Z → Z/2^w; prove once per pair of widths by SAT at small widths or in Lean/Coq if desired); then the RTL product and the spec product are the *same UF application on the same arguments* and Ackermann congruence (equal arguments ⇒ equal results) closes the equality with no multiplier reasoning. Refinement when the property genuinely needs arithmetic (e.g. non-trivial identities `x*y == y*x`, sign, zero, bound lemmas): CEX over UF values → check with the existing exact-integer evaluator (oracle.py, "exact integers") → if the CEX violates true multiplication add the value lemma `x=X ∧ y=Y ⇒ p=X·Y` or tangent/sign/monotonic lemmas (Cimatti et al.'s lemma schemas, TACAS 2017/TOCL 2018 [v]); if it is consistent with true multiplication it is a real counterexample, confirmed by the same replay chain. This reuses c2sva's distinctive asset (C-semantics oracle) as the CEGAR *oracle*, which no generic NIA-abstraction flow has.
 Implementation: yosys `cutpoint`/`abstract -value` on `$mul` cells plus Ackermann constraints emitted by the harness (the harness knows spec-side operands); cell naming from the Round-2 binding map aligns RTL `mul_..._fu_N` with the C expression's AST node. Effort M–L; Risk: medium (loops: UF across iterations is fine for BMC; k-induction with UF is sound as it is an over-approximation of an abstract transition system, with the usual spurious CTI loop).
 Unbounded-IC3 note: word-level IC3 engines (Pono/AVR/rIC3 [v from earlier survey]) do not remove the multiplier hardness by themselves — c10's PDR timeout shows bit-level IC3 fails here; they become useful only on the abstracted system of 4.2.

### Idea 4.3 — Constraint-aware word-level rewriting as a *front* for feed-forward datapath segments (e-graph, ROVER-style)
 For loop-free (or per-segment, see Round 1 Framing 2) datapaths with known latency L: symbolically simulate the RTL for L cycles from the captured inputs (all state is registers fed from inputs: exact, no SAT) to get a word-level term DAG for `ap_return`; take the spec term from the contract; prove equality with an e-graph (egg) using ring/bit-vector rewrite rules **conditioned on the `requires` intervals** (the constraint-aware part of ROVER/Coward–Constantinides–Drane [v]) — expected to settle c10 in milliseconds (x*y*z + x ≡ x*y*z + x after sext-elimination under interval side conditions); anything not closed falls back to SAT. Novelty over Coward et al.: spec is an ACSL term (not RTL), and the result is an artefact usable as a *lemma inside the sequential proof* (segment equality) rather than a standalone equivalence check. Effort L (needs egg or an in-Python e-graph); highest research novelty of the three, lowest priority for the next sprint.

## Round 9 — 2026-11-20 — What A-QED² and G-QED actually define; can an ACSL contract be the single-action spec?

Source: full text of G-QED (DAC 2023; Chattopadhyay, Devarajegowda, D'Agostino, Vavelidou, Ecker, Trippel, Mitra, Barrett, et al.; read from the PDF) and A-QED² (FMCAD 2021, arXiv 2108.06081; read from the PDF; "109 buggy versions of 16 accelerators, ~5× average effort reduction" from the abstract/search). A-QED (DAC 2020) itself not re-read [v by title].

**Exact notions [v, from the papers].**
 - *HA model*: finite transition system with actions A, invalid action a⊥, outputs o⊥; **stable state** = state fixed under any number of invalid actions with no output (≈ our *idle state*).
 - *Relevant state registers (RSR) / relevant state projection rsp(aᵢ,aⱼ)*: the minimal set of state components whose value (together with the inputs) determines the output of the action pair (G-QED Def. 2). In A-QED² batch-mode HAs, `rel(s)` = the relevant part of memory (Def. 6).
 - *Functional consistency (FC)* (G-QED Def. 4; A-QED² Def. 6): same input(s) and same RSR values ⇒ same output, for executions from reset that reach those inputs at *different times/positions* (sequence-based, so BMC from a concrete initial state needs a long sequence). *Strong FC* (A-QED² Def. 7): the two initial states may be *any reachable* states (over-approximated; authors note constraining them is "seldom necessary") ⇒ two short runs suffice. Strong FC ⇒ FC.
 - *Single-action correctness (SAC)* (A-QED² Def. 8; G-QED §III): for each action a, data d and reachable relevant state sr, the output equals `Spec((a,d), sr)` for *some* reachable start state with that relevant state — checked **from reset**, "typically exists in unit tests"; Spec is a user-written *function* of (action, data, RSR).
 - *Response bound (RB)*: output within a time bound (our latency bound).
 - *Theorems*: FC is sound (total correctness ⇒ FC; G-QED Lemma 1) and, **together with SAC, RB and strong connectivity (SC) of the HA, complete** (A-QED² Lemma 3/4: SAC + (strong) FC + SC + RB ⇒ bug found). A-QED² Theorem 1: completeness of decomposition for *functionally composable* sub-accelerators. All of these are for *bounded model checking* (completeness relative to BMC depth; G-QED notes unbounded completeness needs full state-space exploration).
 - Case for HLS: FC at *batch element* granularity (output element j depends only on input element j' and rel) is meaningful for map-like functions (copy, fill, replace, transform) but **not** for prefix-dependent ones (partial_sum, accumulate) unless `rel` is enlarged; *call-level* FC (identical full inputs ⇒ identical full outputs) is trivially true for deterministic circuits from identical states and only exposes dependence on state outside the compared state (uninitialised/stale datapath registers, `static` data). So the bug-finding power of FC on our ABE-style designs is limited to element-wise designs and to state-leak bugs — this refines the Round 7 prediction: put the *element-wise FC* arm only on map-like designs and the *call-level FC with hidden state free* arm on all.

**Can an ACSL contract play SAC's Spec?** Yes, with one change, and it is a useful theorem for the A2 theory section (derived here, not stated in the papers):
 - *Relation instead of function.* G-QED's Spec returns the expected output; an ACSL contract is a relation `Post(σ,σ′)` (and `Frame`). Claim: **FC(call-level, strong) + contract-SAC ⇒ contract preservation in every context.** Proof sketch: by FC the transaction's (output, post-memory) is a function f(inputs, RSR) of the inputs and the relevant state, regardless of hidden state; SAC says every output from a start state with those inputs and RSR satisfies Post; any context with the same inputs and RSR yields the same value f(...), hence satisfies Post. (Needs: Pre-restricted inputs; determinism of the circuit; RSR = memory image + scalar/global state visible to the contract.)
 - *c2sva already does more than SAC from reset*: the harness starts from **arbitrary memory with hidden datapath state evolving over call sequences**, i.e. it checks the contract for all reachable (over-approximated) contexts directly — the over-approximation of reachable relevant states that the A-QED² authors advocate (Def. 8 discussion). So c2sva ≈ "SAC from every context" up to the BMC/induction depth, and FC adds value only where the contract is *loose* (post allows several results): then the contract passes while the circuit's output depends on hidden state (reproducibility bug). Conversely FC is what upgrades *bounded multi-call* coverage to an **unbounded multi-call theorem**: our T2 "every reachable idle state is contract-equivalent to reset" is the call-level *strong FC* with the idle state of the second copy free, i.e. G-QED's *stable-state* condition. Recommend presenting T2 as "call-level strong FC + contract-SAC (= Spec as relation)", citing A-QED²/G-QED, rather than as a new idea; the new part is the contract-as-Spec derived from a deductive C proof and the HLS interface/layout abstraction (RSR = interface memory map via `locate`).
 - *Limits to state:* completeness theorems need SC (every state reachable/returning to stable) — for Vitis, state-leak via non-reset datapath registers breaks "equivalent to reset" exactly when the registers are read before written (a real HLS finding class, matches the auto-init differential).
 - Mapping to our checks: RB = latency harness (`check_lat`); SAC = contract check; FC/strong FC = missing (Round 7 `qed` mode); stable state = idle invariant (A1 structural candidates `ap_idle`, FSM at idle).

## Round 10 — 2026-11-20 — Theorem: window-covering k-induction ≡ BMC to the call diameter (proposed text for docs/theory.md; NOT edited)

**Informal.** If the structural strengthening J guarantees (i) a call's whole transaction lies within a window of L+1 steps and (ii) every accepting state in J behaves like a reachable accepting state, then k-induction with J at any k ≥ L+1 succeeds iff P holds — and its base case is BMC of depth k. A "proof" found only at k ≥ L+1 therefore carries no more evidence than BMC to the call diameter; only proofs with k < L+1 witness genuine inductive content about mid-call states.

**Setting.** Harness H = (S, I, T): finite S (includes DUT, environment and observation registers: snapshots, captured inputs, busy/tracking), I ⊆ S initial states, T ⊆ S×S transition relation (inputs are existentially chosen at each step, folded into T; assumptions restrict T/I). Run = s₀s₁… with s₀∈I and (sᵢ,sᵢ₊₁)∈T. Reach = reachable states. Acc ⊆ S: states in which a start event occurs (`h_start_evt`). Bad ⊆ S: violation states (`h_done_d ∧ ¬φ`), so P ≡ G¬Bad. J ⊆ S: a set with I ⊆ J and T(J) ⊆ J (an inductive invariant; in practice the Houdini-certified conjunction). k-induction with J: *base_k*: no run of length k from I reaches Bad within k steps; *step_k(J)*: no path s₀…s_k with s₀∈J, sᵢ∉Bad (i<k), s_k∈Bad. (Sound: base_k ∧ step_k ⇒ P; J is also assumed at every step — equivalent since J is inductive.)
 Hypotheses, for a number L ("call diameter"):
 - **(WL) window-locality of J:** for every path s₀…s_m (m ≥ L+1... any m) in J-states with s_m ∈ Bad there is j ∈ [m−L, m] with s_j ∈ Acc. (Bad is witnessed by a transaction that *started* within the last L steps. In c2sva: `h_done_d` requires `h_busy`, which is set only at a start event and cleared at `ap_done`; the response bound L must hold from every J state, which requires the call preconditions — e.g. `n ≤ N` — to be part of J: the "call-requires" candidates are exactly what makes (WL) true; without them CTIs start with n=128 and the bound L fails.)
 - **(BIS) idle bisimilarity:** there is a relation ∼ ⊆ J×Reach (a simulation of J-states by reachable states) such that for every u∈J∩Acc there is u′∈Reach∩Acc with u∼u′; if u∼u′ then (u∈Bad ⇔ u′∈Bad) and for every (u,v)∈T there is (u′,v′)∈T with v∼v′ (forward simulation, preserving Bad). Let d be the least number such that every u′ obtained this way can be taken with reach-depth ≤ d (d=∞ if none; d=0/1 when the reset state with arbitrary memory is bisimilar to every accepting J-state — the "idle-state equivalent to reset" condition, T2).
**Theorem.** Assume (WL) and (BIS) with parameters L, d, and let K ≥ L+1. Then
 1. step_K(J) holds iff P holds on H (i.e. H ⊨ G¬Bad). 
 2. P holds iff BMC to depth D = d+L finds no Bad state (and BMC to any depth ≥ D too).
 3. Consequently k-induction with J at K succeeds iff BMC_{max(K,D)} is UNSAT; if d ≤ 1 and K = L+1 then it succeeds iff BMC_K is UNSAT, i.e. the induction step is redundant.
*Proof sketch.* (1, ⇐) Suppose a path π = s₀…s_K with s₀∈J, s_K∈Bad. J inductive ⇒ all sᵢ∈J. By (WL) there is j∈[K−L,K] with s_j∈Acc (so j ≥ 1 since K ≥ L+1). By (BIS) pick u′∈Reach∩Acc, s_j∼u′. Forward-simulate the suffix s_j…s_K from u′ to a run u′…v′ with s_K∼v′; Bad preserved ⇒ v′∈Bad, and v′ is reachable (u′ reachable, then T-steps): contradicts P. (1, ⇒) is the contrapositive of soundness plus the fact that a reachable Bad path from I with Bad at step m has, by (WL), a start in the last L steps; its prefix up to the start is reachable, so a violating step_K path exists after prepending any K−(m−j) reachable... — here the prefix is padded using runs of T from the reachable accepting state (stuttering at idle is allowed by environment), standard. (2) The violating run of (1,⇐) can be rotated to start at u′, which is reached at depth ≤ d; the transaction then needs ≤ L steps. (3) base_K = BMC_K; combine with 1, 2. ∎
**Corollaries and what they imply for reporting.**
 - **C1 (window-covering proofs are BMC proofs).** Any structural-only success at K ≥ L+1 certifies only: J inductive, (WL), (BIS) and BMC_K. It is a valid "unbounded in time/number of calls" proof *for the fixed N* (L = L(N) is a finite constant), identical in strength to the completeness-threshold argument of BMC (cf. Kroening & Strichman, recurrence diameter; [unv], from earlier survey). It says nothing about whether J contains loop-carried information; and K must grow with L(N) = Θ(N) (or Θ(N²)).
 - **C2 (inductive proofs).** If step_k(J) and base_k hold for some k ≤ L with the *same* hypothesis (WL) restricted to windows ≤ k impossible, then J∩Busy excludes the spurious mid-call start states of paths shorter than the call: J necessarily contains information on busy states (loop-counter ranges alone suffice only if the property is counter-local; array-history facts otherwise). This is the sense in which "C artefacts are necessary" is meaningful; a measurable surrogate is ρ = k_min/(L+1) < 1.
 - **C3 (N-dependence).** For fixed deployment size, k_min(pool) ≤ L+1 whenever (WL)+(BIS) hold for that pool; hence k_min(structural) ≤ L(N)+1 always, with equality only in the worst case; *the interesting empirical question is whether it is smaller*. N-independence of k_min is only possible if J∩Busy carries loop-carried facts.
 - **Reporting rules for the ablation (proposal):** (a) report for each design L (csynth max latency or the RB-proved bound) and the column "window-covering?" = (k ≥ L+1); (b) label proofs with k ≥ L+1 as "BMC-complete (call-diameter)" and proofs with k ≤ L as "inductive"; the headline "unbounded 16/17" should be accompanied by the split; (c) the ablation arms must be compared via k_min (smallest k with PASS) not status at a fixed k; (d) with the existing data, L=8 ⇒ L+1=9, so k ∈ {12,16} proofs are window-covering and k ∈ {4,8} are inductive; c02 (L16,k12) and is_heap (L8,k12): the latter's k=12 ≥ 9 means window-covering *only if* (BIS) holds, which structural-only did not give (hls UNKNOWN) — contract-derived facts (call-requires, i.e. (WL)'s precondition) were what made the bound L hold; (e) add a column for whether `requires` bounds are in J, since (WL) depends on them.
 - **Remark (pipelined/overlapping calls):** replace L by L + (pipeline depth)·II (calls in flight), same proof with the window covering all in-flight transactions.
 - **Remark (what a failing check means):** if step_K(J) fails for all K ≥ L+1 although BMC passes, then (BIS) is false for J: some accepting J-state is not simulated by a reachable one — i.e. J misses an idle-state invariant (e.g. dead datapath registers) and this is checkable as a two-copy idle miter (T2).

**Diagnosis of the c12 timeout from the artefacts.** c12 `cand` = structural 38, call-requires 4, call-frame 2, **loop-invariant 40**, loop-variant 8, loop-assigns 4 (≈96); the E1 `houdini` result for c12 is "induction timeout at k=16"; same-size pools succeed at smaller k (c09: 226 candidates at k=4 in 1.6 s; lower_bound 93 candidates, k=16, 615 s). So cost ≈ (#candidates alive) × k-unrolled copies × rounds, and the 40 loop-invariant candidates are ~8 placements × 5 clauses (Round 2: one placement per invariant suffices with the binding map). The volume problem is mostly *placement multiplicity* and *k×|pool| unrolling in each round*, not the structural/contract families.

**Soundness invariant for any scheme.** Drops by *base case* or by a *positive example* are final (the candidate is false on a reachable behaviour). Drops by the *induction step* are not final until all candidate families have been included (a candidate may need another family's invariant to be inductive). Therefore any staging/ordering is sound if the **last pass runs over every non-refuted candidate** and a final k-induction of the surviving conjunction certifies the result. Final answer = the usual greatest inductive subset; staging only changes the cost.

**Recommended scheme (one): "example-pruned, cone-sliced worklist Houdini" (H-Houdini-lite), 3 steps, implementable in prove.py without new solver features.**
 1. *Positive-example prefilter (no SMT).* Run the RTL on ~100–300 random calls (the existing replay/cosim vectors + the BMC models already produced for candidate refutation; Verilator or `yosys sim`, a few seconds), evaluate each candidate on every cycle where its guard holds; drop all falsified candidates. Also re-use the C-side traces to filter *C-invariant placements* (the placement whose value matches the C trace is the right one — this is the cheap alternative to the binding map and its fallback). Expected: removes most of the ~8 placement variants and the false guard/state combinations; based on the logged `base_dropped` (e.g. lower_bound 28 of 93, E1 c10 2 of 13) the SMT-based base filter currently does this work at BMC cost.
 2. *Cone-sliced relative inductive checks with a worklist.* For each surviving candidate c, slice the transition system to the k-step fan-in cone of the registers c mentions (`yosys cone`/`select %ci*`, or the existing tap machinery) and check "c inductive at depth k assuming the currently alive candidates **inside that cone**". Failure ⇒ drop c, push into the worklist only the candidates whose cone contains a register of c. Checks are independent per candidate ⇒ run `n_jobs` in parallel (the machine has idle cores between campaigns). Property-directed pruning (optional, from H-Houdini): first compute the closure of the *contract assertion's* cone under candidate dependences and only check candidates inside it; candidates outside cannot influence the property's inductiveness at the same depth (they are still needed if the cone grows with k: take the k-step cone).
 3. *Final monolithic confirmation, once.* One k-induction run on (property, surviving conjunction) — the existing `kind+inv` step — so the certificate remains the same object as today. (H-Houdini avoids even this by construction; we keep it as a cheap soundness anchor.)
 *Optional 4, CTI-guided activation (ICE-flavoured), if pools remain too large:* when the monolithic step fails with a CTI s₀…s_k, rank still-inactive candidates by (violated at s₀, consistent with all positive examples, small cone), activate the top few, repeat — a lazy variant that adds candidates only on demand; AutoINV's ranker (fan-in cone ∩ CTI-cube frequency) is the same idea. Note: staging by family order (structural → contract → C) is *not needed* with step 2 (cones already localise), and is only a heuristic ordering.
 *Also:* drop `loop-variant`/progress candidates from the contract proof and generate them only for the latency-bound proof (8–36 candidates per design; they are 8% of c12's pool but 18/93 in lower_bound).
 *Expected effect (estimates, to be measured):* candidate count after step 1 ≈ 3–8× smaller for designs with many placements; per-check SAT size scales with the cone, not the whole netlist (for c12-style single-loop designs the cone of one candidate is a small fraction of the registers); worklist avoids re-solving unaffected candidates; wall-clock 3–10× on the E1 timeout case, with up to #cores additional speed-up. **Metrics:** candidates alive after each step; SAT calls and total solver seconds per design; time-to-fixpoint; identity of the final certified set vs the old Houdini (must be equal when no timeout occurred — an end-to-end regression test); count of designs with censored (timeout) entries in the k_min table; k reached before timeout.

## Round 18 — 2026-11-21 — Flush-prefix refinement: theorem text and proof sketch (proposal; theory.md NOT edited)

**Context.** Round 10 (window theorem) predicted structural-only success for K ≥ L+1; E1 data showed k_min(hls) ∈ (12,16] for L=8 and ∈ (16,24] for L=16. Refinement: idle-bisimilarity holds only for accepting states that lie at least F steps into a J-path.

**Definitions** (as in Round 10: H=(S,I,T), Reach, Acc, Bad, inductive J ⊇ I with T(J)⊆J, k-induction base_k/step_k(J)). Let L be the *window bound* and F the *flush depth*:
 - **(WL_L)** every J-path s₀…s_m with s_m ∈ Bad has a start state s_j ∈ Acc with m−L ≤ j ≤ m.
 - **(BIS_F)** for every J-path s₀…s_j with j ≥ F and s_j ∈ Acc, there is u′ ∈ Reach ∩ Acc and a forward simulation ∼ ⊆ J×Reach with s_j ∼ u′, such that ∼ preserves Bad and matches the environment's choices (Round 10 (BIS) restricted to positions j ≥ F).
 Let F*(J) be the least F for which (BIS_F) holds (F* = ∞ if none; F* ≤ F′ for every J′ ⊇… monotone: more invariants cannot increase F*), and L*(J) the least L for which (WL_L) holds.

**Theorem (flush-window).** Assume (WL_L) and (BIS_F) and let K ≥ F+L+1. Then step_K(J) holds whenever H ⊨ P (no Bad state is reachable), hence k-induction with J at K is complete: *base_K ∧ step_K(J) ⇔ BMC_K passes ∧ H ⊨ P*, and the base case BMC_K already covers every run in which Bad occurs within K steps. If moreover d is the reach-depth of the simulating states u′ (Round 10), then H ⊨ P ⇔ BMC_{d+L} passes.
*Proof sketch.* Suppose π = s₀…s_K with s₀ ∈ J, s_K ∈ Bad (a step-case counterexample). By (WL_L) there is j ≥ K−L ≥ F+1 with s_j ∈ Acc; the prefix s₀…s_j is a J-path of length j ≥ F, so (BIS_F) gives a reachable accepting u′ ∼ s_j. Forward-simulate the suffix s_j…s_K from u′ to a run ending in v′ with s_K ∼ v′; ∼ preserves Bad, so v′ ∈ Bad is reachable, contradicting H ⊨ P. Thus no step-case counterexample exists. Conversely, if P fails, base_K fails for K ≥ (shortest violating run), or in general P fails ⇒ k-induction cannot prove it (soundness). The BMC statement follows because the simulating run has length ≤ d + L. ∎
**Lower-bound statement (explains "≈", makes F measurable).** For a given J let F* = F*(J), L* = L*(J). If F* > 0 and the spurious accepting state s_j at position F*−1 can reach Bad within L* steps in J (i.e. the violation is not excluded by J), then step_k(J) fails for every k ≤ F*−1+L*; so **k_min(J) = F*(J) + L*(J) + 1 when the "tightness condition" (the earliest non-simulable accepting J-state leads to a J-reachable Bad within the window) holds, and k_min(J) ≤ F*(J) + L*(J) + 1 always.** The tightness condition is exactly what a CTI at k = k_min − 1 exhibits: a step counterexample whose accepting state lies at position F*−1.
**What F means in HLS terms.** A J-path of length < F reaching Acc has its start state "too close" to s₀: control/datapath registers that J does not constrain (pipeline-valid bits `ap_enable_reg_ppX_iterY`, `ap_loop_init`, loop-exit flags, FSM states of sub-modules) can still carry a mid-call configuration that is not a simulable idle state; after F steps the in-flight work has drained (F ≤ L is the trivial bound: wait for the call in flight to finish) and only dead data registers differ. Adding the *idle facts* (all control regs at idle values when `ap_idle`/FSM idle; pipeline valid bits clear; sub-module `ap_idle`) to J reduces F* — in the limit F*=0 (then k_min = L+1, the Round-10 value). So **F is a quantitative measure of the completeness of the structural idle invariant**, and "k_min(hls) − (L+1)" is directly comparable across designs and across Vitis configs (pipelined designs expected to have larger F: depth D of the pipeline).
**Checking against the fine-ladder data (k=9..16 on c03/c07, being run).** (i) Prediction P-F1: k_min(hls) = L+1+F* with F* independent of L (constant), observed bracket F* ∈ [3,7] for L=8 (k_min∈(12,16]) and F* ≤ 7 for L=16 (k_min∈(16,24]); alternative P-F2: F* ∝ L (flush = drain the call in flight) ⇒ k_min ≈ 2L+1 = 17 for L=8, 33 for L=16: the L=16 data (k_min ≤ 24 < 33) already **refutes P-F2** for c02/c16; so F* is likely a small constant ≈ pipeline depth/prologue. (ii) For c03 (L=8): the fine ladder returns v = k_min(hls) ∈ {13,…,16} ⇒ F* = v−9 ∈ {4,…,7}; if v=13 then F*=4 etc. (iii) If c07 (D=1 loop) has smaller F* than c03 (D=2, II=1), F* tracks the pipeline depth/overlap. (iv) If k_min(hls) = 9 + F* with the same F* at N=2,4,8 then slope(N) = slope(L(N)): the N-scaling plot's structural curve is the diagonal shifted by F*. (v) A decisive diagnostic: print the CTI at k = k_min−1 for c03 and list the registers that are not simulable (compare against the reachable states by simulation); they name the missing idle facts; add them and re-measure — F* should drop (if not, (BIS) fails for a different reason). (vi) k_min(none) > 32 is consistent with (WL_L) failing for J=∅ (no call-requires bound ⇒ L*=∞).
**How to report.** Table columns L+1, F*+L+1 (measured), F* = k_min − L − 1, with F* ≥ 0 required (a negative value would mean the Round-10 window assumption is wrong or the latency used is an over-estimate of the harness's actual window: check `latency` in prove.json vs the latency harness result).  - Gap statement (to the best of our knowledge, searched 2026-11-21): no work derives **per-variable iteration lags from the HLS schedule and uses them to instantiate source-level (ACSL) loop invariants on pipelined RTL**.

**The lag rule is a derivable, standard quantity from the schedule.** Notation: pipelined loop with initiation interval II and depth D (the `Pipeline-n : II = …, D = …, States = {1..D}` line); an operation in pipeline state s (1-based) of iteration m executes in the cycle where iteration m+j is in state s−j·II. The loop-header state of iteration i (counter test, first stage) is evaluated when iteration i is in state 1. Iteration i−j is then in state 1+j·II. Its operation in state s_op is **not yet committed** (register/memory write lands at the clock edge) iff s_op ≥ 1+j·II. Hence for a variable v defined (alloca `store`, or memory `store` to `*_addr`) in state s_def(v):
   **δ(v) = ⌊(s_def(v) − 1)/II⌋** = the number of *earlier iterations whose update of v is still in flight at the header cycle*; δ(v)=0 iff s_def(v) ≤ II.
 Checks against reports: c08 (II=1, store in ST_2) ⇒ δ=1 ✓ (matches the dropped prefix invariant, lag 1); c07 (store in ST_1) ⇒ δ=0 ✓ (prefix invariant kept); equal_range's lower_bound loop (II=1, `left`/`right` stores in ST_3) ⇒ δ=2 — explains why name-based, register-tapped, unlagged callee invariants had 0/6 survivors; remove (II=2, store ST_2) ⇒ δ=0 ✓ (C-needed, gain); reverse (II=3, stores ST_2/ST_3) ⇒ δ=0.
 **Relation to the implemented counter-lag candidates (origin `loop-invariant-lag`, lags 1,2 on the loop counter).** A quantified prefix invariant `∀j<i …` evaluated on registers is consistent iff the counter and every variable/memory it mentions have *the same lag*. If the counter is current (δ_i=0, stage 1) and the dependent variable/memory lags by δ_dep, the verbatim invariant is off by δ_dep iterations; replacing `i` by `i−(δ_dep−δ_i)` fixes it. So counter-only lags {1,2} cover every case where the *relative* lag δ_dep − δ_i ∈ {1,2}, which is the case in all designs seen (δ_max ≤ 2: binary_search has δ=2, all others ≤ 1). Cases it does **not** cover: (a) invariants mentioning two variables with *different* δ and no counter (e.g. `left`, `right` in different stages; not seen: both δ equal); (b) read-only loops where every carried variable has the same δ (lower_bound/upper_bound: `left`,`right` both δ=1): relative lag 0, so lagged candidates cannot help — prediction in Round 22.
 **How to compute it (no new tooling needed beyond Round 2):** from `*.verbose.sched.rpt` take, for the loop's `Pipeline-n` states set, every `store` whose target is an alloca (C scalar) or `*_addr` (array) with its `ST_s` number and II. For scalars read through a forwarding mux (`ap_sig_allocacmp_<ssa>`, listed in the Multiplexer table of the `.verbose.rpt`) the tap can alternatively be moved to the forwarded value and δ(v)=0 — two equivalent ways to restore consistency (lag the invariant, or tap the forwarded signal). Memory is never forwarded to the header, so memory-dependent clauses always need the lag.

## Round 23 — 2026-11-21 — Post-loop / epilogue regions: a principled rule, guard definition, and why the lag must be dynamic

**What the RTL of c08 shows (read-only).** The whole function is one function-level pipelined loop (II=1, D=2, one FSM state `ap_ST_fsm_pp0_stage0`). Phase information is therefore *not* in the FSM state; it is in: `ap_enable_reg_pp0_iter0 = ap_start_int` (stage-1 valid), `ap_enable_reg_pp0_iter1` (stage-2 valid), `ap_condition_exit_pp0_iter0_stage0` (exit test: `icmp_ln13 == 0` while stage 1 valid), `ap_loop_init` (flow-control module: set at reset and at `ap_loop_exit_ready`, cleared at the first `ap_ready_int`), `ap_done_reg`. Facts: (i) `ap_ready = ap_loop_exit_ready` and `ap_done = ap_done_int = ap_loop_exit_ready ? 1 : ap_done_reg`, i.e. **`ap_done`/`ap_ready` are asserted in the very cycle of the exit test**, in which iteration n−1's stage 2 (the store of a[n−1]) executes; the harness reads the post-state one cycle later, when that write has landed. (ii) After the exit cycle the counter register `i_fu` is frozen (its increment is predicated by `icmp_ln13`), `ap_loop_init=1` again, and `ap_sig_allocacmp_i_1` is **forced to 0 by `ap_loop_init`**, so the forwarded tap shows i=0 in the post-exit/idle phase while the register still holds i=n. Hence a loop-invariant instance taken on the forwarded signal is meaningless after exit; the register must be used there.

**Why the fixed-lag candidates stop at the exit.** The step-case start state in the CTI is "exited, done pending, cells not incremented": every loop-derived candidate is guarded by `iter0`/`iter1`/state-of-loop (RUN), none by the phase after the exit test, so memory and snapshot registers are unconstrained and the post-condition fails within a few steps. This is exactly the three-region structure of the Puri–Ray–Hao–Xie invariant (below): the loop invariant holds in the *prologue → full stage*, and the *epilogue* is what completes the partially executed iterations.

**Known precedent (read in full, arXiv 1406.1562, ACL2 2014).** Their "correspondence relation" between sequential and pipelined CCDFGs: starting from the same state, *executing the pipeline prologue and k full-stage iterations is equal to executing k sequential iterations, followed by m scheduling steps of the next sequential iteration, then (m−II) steps of the one after, then (m−2·II), … while positive* (their `get-m-blocks-seq`; m = number of scheduling steps of the first iteration inside the prologue, II = pipeline interval); the **epilogue exactly constitutes the incomplete scheduling steps** named by the invariant, so equivalence follows from the invariant plus the epilogue; the proof is by induction on k with base case "prologue + one full stage". They stress that the invariant "must explicitly capture the state of the executions that have been partially completed", and that an unrolling-based correspondence fails because of the back edge. Translation to our setting: **the RTL state at the back edge = C state after (i − δ_eff) completed iterations plus the staircase of partially executed iterations**; a source invariant I (stated on C states at loop headers) transfers as I(c_eff) with c_eff = number of *completed* iterations, and the epilogue rule is "complete the staircase".

**Candidate rule (R-phase).** For a loop L with initiation interval II, depth D, pipeline-valid bits v_s = `ap_enable_reg_ppX_iter<s>` (s = 0..D−1; v_s true ⇔ some iteration is in stage s+1; v_0 may be `ap_start_int`), exit condition `x` (the header's conditional branch false edge: the `icmp` op named in the report, RTL `icmp_..._fu_N_p2` ∧ v_0), and a counter-like variable i (affine C loop variable) with C loop invariant clauses I(i, mem, \at(·,Pre)):
 1. *Dynamic commit count.* For a quantity v (memory store or scalar) defined in stage s_def, the number of earlier iterations whose update is still uncommitted is the number of valid in-flight iterations among stages 1+j·II, j=1..δ(v), δ(v)=⌊(s_def−1)/II⌋: **c_eff(v) = i − Σ_{j=1..δ(v)} v_{j·II}** (zero-based bit index j·II ↔ stage 1+j·II). In steady state c_eff = i−δ (the fixed lag already implemented), in fill/drain it is exact. Candidate: `LIVE_or_DRAIN ⇒ I[i ↦ c_eff]` on the forwarded counter tap. (The fixed lags −1,−2 are special cases that are *too weak* when the pipeline has drained: they cannot state "all n cells done".)
 2. *Exit fact.* Ghost `g_exit` (harness): set in the cycle where `x` holds (v_0 ∧ ¬cond), cleared at `h_start_evt`; derivable from the report. Candidate in the exit cycle and all later phases until the next start: `g_exit ⇒ ¬cond(i_reg)` and `g_exit ⇒ I[i_reg ↦ c_eff]`, **tapped on the counter register `i_fu`** (frozen), not on the forwarded signal (which `ap_loop_init` forces to 0).
 3. *Write-port instances in DRAIN/POST* (already implemented for RUN): extend the guard of `we ⇒ G(addr) ⇒ d == E(addr)` from loop-state to `(v_s for s ≥ 1) ∨ g_exit` (the pending write of the last iteration is issued in the exit cycle).
 4. *Post-persistence of the contract.* `g_exit ∧ ¬(v_1 ∨ … ∨ v_{D−1}) ⇒ φ_post` for each translated `ensures` clause φ_post (on snapshot `o`, memory `m`), until the next start: the harness checks φ only in the cycle after `ap_done`; as an *invariant* it also covers later idle cycles, and it is exactly the lemma that the idle-flush F needs (the state at the start of the next call carries the previous call's post-state). Plain stability: no valid stage ∧ no start ⇒ no write.
 Guard summary derivable from the schedule/RTL: LIVE = (call started) ∧ ¬g_exit; DRAIN = g_exit ∧ ∃s≥1 v_s; POST = g_exit ∧ ∀s v_s=0 (until `h_start_evt`). For loops embedded in a longer FSM (sequential post-loop states), POST also includes the FSM states reachable from the loop exit edge up to `ret` (the "FSM state transitions" list in `*.verbose.sched.rpt`) and the ghost is set by the FSM edge leaving the loop state set; for non-pipelined loops DRAIN is empty and c_eff = i.
 *Why Houdini filters it safely:* all of the above are candidates; wrong guards are refuted by base/BMC.
 *What it should fix and what it will not.* Fixes CTIs starting in DRAIN/POST (the observed one). Not covered: PRE/start-cycle phases (stale `i_fu` from the previous call at the first iteration; handled by the forwarded `ap_loop_init` mux ⇒ i=0), and garbage in *unreachable combinations of valid bits* (v_1=1 with v_0=0 and g_exit=0, i.e. a drain without an exit): add the structural facts `v_s ⇒ (v_{s−1} was … )` = pipeline-valid shift-register facts (`v_1 ⇒ prev v_0` is a register relation, derivable from the Verilog: `ap_enable_reg_pp0_iter1 <= ap_start_int` when not exiting) so that the valid vector is consistent with the ghost phase.
 *Relation to cut-points/Kairos.* The three phases are the regions of a cut-point decomposition (prologue G_p, full stage G_l, epilogue G_e in Puri et al.; Kairos' regions are user-delimited latency-insensitive regions, FMCAD 2019): R-phase is the contract-level analogue: I at the LIVE cut, I∧exit at the DRAIN→POST cut, Post at the POST region.
 *Falsification:* if with R-phase c08's CTI at k=8 disappears and k_min(all) ≤ 8 (< L+1), the mechanism is confirmed; if the CTI moves to a different phase, log which valid-bit combination (this enumerates the missing structural facts, each of which is finite: 2^D combinations).

## Round 24 — 2026-11-21 — Call-age counter: harness artefact or not, and the clean formulation

**Facts.** The harness `h_cyc` is a 16-bit up-counter (cycles since start; used for the latency proof `h_busy ⇒ h_cyc ≤ B` and the progress candidates `h_cyc ≤ m·i + c`). In a k-induction step the first state is arbitrary, so `h_cyc` may be 65533 and wraps to 0 in 3 steps, creating a trajectory (a busy call "younger" after having been "older") that no real run has. A wrapped value also makes *violations of progress candidates disappear* (the candidate is checked on the wrapped value).
**Verdict.** (i) The wrap is a *harness-model artefact* (a modular counter is not part of the property); a counter that is only used for the bound B needs only values 0..B+1. (ii) But it is not the root cause of the c08 CTI: the age in the CTI state (65533 ∧ busy) would be excluded by *any* certified fact `busy ⇒ age ≤ c + m·i` or by the RB lemma `busy ⇒ age ≤ B`; the CTI survives because no such fact is guarded for the DRAIN/POST phases (Round 23: the progress family is guarded by loop states). So fix the guard coverage first; the width/saturation fix is hygiene.
**Clean formulations (pick one).**
 A. *Saturating bounded age.* width w = ⌈log2(B+2)⌉ (+1 slack), `age' = start_evt ? 0 : (busy ? (age==MAX ? MAX : age+1) : age)`; MAX = 2^w−1 > B. Property RB: `busy ⇒ age ≤ B`. Unreachable large ages collapse onto MAX, a state violating RB; wrap cannot occur. For BMC runs shorter than MAX nothing changes. (Our B is the proved bound; the harness needs B before the latency proof: use the BMC latency-search bound with a margin, or the structural bound `Σ II·trip + D` from the report.)
 B. *Two-phase proof with RB as lemma (preferred; also gives the theory its (WL)).* Phase 1: prove RB (Theorem 3, progress candidates) for all executions; Phase 2: the contract proof treats the certified RB invariants as members of J. Then (WL_L) of the Round-10/18 theorem *is* "RB ∈ J" with L=B, instead of an external hypothesis; CTIs with huge ages vanish by construction (age ≤ B < 2^w) and the width can be exactly ⌈log2(B+2)⌉. Dependency is one-way if the RB proof uses only call-requires and structural/C-loop-bound candidates (check that it does not use the contract postcondition; plan.md says it uses "contract invariants (assumed)" — verify that this means preconditions, not postconditions, otherwise a circularity needs a joint induction).
 C. *Age-free alternative.* Replace `age` by structural stage counters (v_s) plus the loop counter: RB then follows from `i ≤ n ≤ N` and bounded drain; no unbounded counter exists to wrap. The age is only needed to *state* RB for the harness; using B + two-phase proof avoids it in the contract proof entirely.
**Phased progress family (replaces the loop-guarded one).** `PRE: age ≤ c₀` (prologue length, from the report), `LIVE/DRAIN/POST (g_exit ghost): age ≤ c₀ + m·min(i_reg, N)` with m = cycles per iteration (II), plus `age ≤ B` once saturated; all guards from the same ghost/valid-bit definitions as Round 23.
**Effect on F.** The flush prefix F (≈4 at L=8 from the fine ladder: c03 13, c07 structural 13, both L=8 ⇒ F=4 independent of D=2 vs D=1) is the number of steps needed to leave the "garbage phase combinations"; with RB∈J and the phase facts F should shrink toward 0, k_min(hls) → L+1 = 9 for c03/c07. A direct, cheap test of both Round 18 and this round: add RB (phase-guarded) and the valid-bit consistency facts to the *structural* pool and re-run the fine ladder on c03/c07: prediction k_min(hls) ≤ 10 (F ≤ 1). ## Round 26 — 2026-11-21 — Exit ghost: Vitis signals, exact templates, minimal set for the c05 CTI

**(B) `ordered` (task_452) — the axioms are inconsistent; "unproved" is the wrong verdict.** Axioms: base (m≥n ⇒ ordered), split (m≤n≤k ⇒ ordered(m,k) ⇔ ordered(m,n) ∧ ordered(n,k)), two (m<n ⇒ ordered(m,n) ⇔ a[m] ≤ a[n−1]). **(C) A second, complete validation route for the N-cell semantics: bounded model enumeration (BME) / finite instantiation (FIV).** The translator's claims are relative to N cells and the C-level data are small (equality/order only ⇒ values in {0..N−1} suffice by order-isomorphism); so the right validation for a lifted definition is exactly in that finite semantics.
 - *Axiomatic (non-inductive) definitions:* instantiate each axiom for all index tuples with 0≤m,n,k≤N and p over a small domain; symbols (`count(m,n,p)` as UF values per tuple), memory cells as symbolic integers; (i) **consistency**: instances SAT? Soundness: finite instantiation of universal axioms *weakens* the hypotheses, so entailment on the instances is a valid conclusion for the N-domain... but consistency detection (SAT of instances) is only evidence of consistency, UNSAT is proof of inconsistency. ## Round 31 — 2026-11-21 — New directions checked against literature (inputs to the consolidation)

New ideas evaluated this round (beyond R1–R30); literature confirmed by search unless marked.
 * **Contract-guided HLS (pragma synthesis from proved facts, check closes the loop).** Motivation confirmed: Vitis UG1399 states that a false `dependence … inter false` "can result in incorrect hardware"; pragma insertion tools trust their own analysis; Pouchet et al. (FPGA 2024) verify source-to-source rewrites only. Concrete mapping: `\separated(a,b)` → `dependence variable=a inter false`; ranges → `ap_int` width/`loop_tripcount`; `assigns` frames → partition/dataflow splitting legality. Novelty claim (to the best of this search): no flow derives HLS hints from deductive contract proofs and re-checks the optimised RTL against the same contract.
 * **Pragma audit / contract-oracle differential testing of HLS tools.** Closest: Herklotz & Wickerson, "Finding and Understanding Bugs in FPGA Synthesis Tools", FPGA 2020 (Verismith; 11 bugs reported, 6 fixed; random Verilog + equivalence) [v]; also "Toward Understanding FPGA Synthesis Tool Bugs" (ACM 10.1145/3718737, seen, unread) and a 2025 mutation-based FPGA synthesis fuzzing arXiv (2508.15536, seen). They test *logic* synthesis, not HLS directives with source specs. Directive seeding + contract oracle + config/version/tool differential is new; the problem statement's Bambu/XLS give the multi-tool angle.
 * **Proof-carrying RTL bundle + certificate repair.** Prior: Proof-Carrying Hardware (Drzevitzky, Kastens, Platzner, ReConFig 2009) [v] and "Proof-Carrying Hardware via Inductive Invariants" (ACM 10.1145/3054743) [v, authors not read]: producer ships an inductive-invariant certificate, consumer checks it. New: the certificate is derived from a *source contract proof*, repaired across HLS configurations by the (II,D,δ) rule, with a measured portability metric.
 * **Proof-based equivalent-mutant classification (new, cheap).** Survivors that A1 proves contract-preserving are *equivalent with respect to the contract* (a sharper label than "no violation found"); applies to the 76 E4 and 8 ABE survivors; strengthens the mutation-score claim (denominator without contract-equivalent mutants). Closest idea family: trivial-compiler-equivalence for equivalent mutants (Papadakis et al. ICSE 2015) [unv].
 * **Report validation.** csynth latency/II/depth are claims about the RTL; the response-bound proof (16/17) can be compared with the reported latency to detect report bugs. Cheap by-product of existing data (compare `latency` search result vs report max latency per design).
 * **Dataflow compositional proofs with channel-content invariants** (R11): kept as "also considered".
